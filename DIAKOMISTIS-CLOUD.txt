ΠΩΣ ΔΟΥΛΕΥΕΙ
Το πρόγραμμα τρέχει σε ΕΝΑ μέρος, τον «διακομιστή». Όλα τα PC και τα κινητά το ανοίγουν σαν σελίδα, ο καθένας με
το δικό του όνομα και κωδικό. Γι' αυτό είναι πάντα συγχρονισμένα: ό,τι αλλάζει ένας (έγκριση, τιμή, αντιπρόσωπος)
φαίνεται ΑΜΕΣΩΣ σε όλους, και ένα κινητό που ξυπνάει ενημερώνεται μόνο του.
- Οι αυτόματες εργασίες (ανάγνωση sites, τιμοκατάλογοι, έρευνα αγοράς, διορθώσεις) γίνονται μία φορά, στον
  διακομιστή. Τα PC του μαγαζιού μένουν ελαφριά (μόνο ένας browser).
- Το AI (Ollama), αν το βάλεις, χρειάζεται ΜΟΝΟ σε ένα μέρος.
- Ένας κοινός φάκελος (OneDrive) ΔΕΝ είναι λύση: με δύο PC ανοιχτά ο ένας σβήνει τις αλλαγές του άλλου.

ΠΟΙΟ ΝΑ ΔΙΑΛΕΞΕΙΣ
  ★ ΔΩΡΕΑΝ, ΧΩΡΙΣ ΚΑΡΤΑ, ΜΟΝΙΜΟ — προτείνεται: Render + ιδιωτικό αποθετήριο GitHub (δες αμέσως παρακάτω),
     και μετά (★★) κοινή βάση Supabase και τα PC των μαγαζιών για τη βαριά δουλειά.
     Ανοίγει από παντού (κινητό, PC, δύο μαγαζιά) με όλα τα PC κλειστά. Στήνεται όλο από το κινητό.
  Α. ΔΩΡΕΑΝ ΣΤΟ CLOUD, 24 ΩΡΕΣ — προτείνεται
     Oracle Cloud «Always Free». Δουλεύει με ΟΛΑ τα PC κλειστά: από τα δύο μαγαζιά, από το σπίτι, από το κινητό,
     παντού. Η ημερήσια έρευνα γίνεται τη νύχτα και είναι έτοιμη το πρωί. Κόστος 0 €.
     Θέλει κάρτα μόνο για επιβεβαίωση ταυτότητας στην εγγραφή.
  Β. ΔΩΡΕΑΝ, ΧΩΡΙΣ ΚΑΡΤΑ — μόνο μέσα στο μαγαζί
     Ένα PC του μαγαζιού γίνεται ο διακομιστής (SF-Kentro-Server.cmd). Κινητά και PC στο ίδιο Wi-Fi μπαίνουν με
     QR. Δουλεύει μόνο όσο είναι ανοιχτό αυτό το PC και μόνο μέσα σε αυτό το μαγαζί.
  Δ. ΓΙΑ ΑΡΧΗ, ΧΩΡΙΣ ΚΑΡΤΑ ΚΑΙ ΧΩΡΙΣ ΥΠΟΛΟΓΙΣΤΗ — GitHub Codespaces (δες πιο κάτω): ο λογαριασμός GitHub αρκεί,
     όλα από το κινητό. Δεν είναι 24 ώρες: κοιμάται όταν δεν το χρησιμοποιείς και το ξυπνάς με ένα πάτημα.
  Γ. ΟΠΩΣ ΠΡΙΝ: ένας υπολογιστής μόνος του (SF-Kentro.cmd).
Μπορείς να ξεκινήσεις σήμερα με το Β και να πας στο Α όποτε θέλεις: τα δεδομένα μεταφέρονται με ένα αρχείο.

★ RENDER + GITHUB — ΔΩΡΕΑΝ, ΧΩΡΙΣ ΚΑΡΤΑ, ΜΟΝΙΜΟ (όλα από το κινητό, περίπου 20 λεπτά)
================================================================================
Το πρόγραμμα τρέχει δωρεάν στο Render. Ο δίσκος του Render σβήνεται σε κάθε επανεκκίνηση, γι' αυτό το πρόγραμμα
φυλάει μόνο του όλα τα δεδομένα σε ένα ΙΔΙΩΤΙΚΟ αποθετήριο στο GitHub σου (2 λεπτά μετά από κάθε αλλαγή, μόνο ό,τι
άλλαξε, και όταν σταματά) και τα ξαναδιαβάζει σε κάθε εκκίνηση. Εκεί θα δεις έναν φάκελο «data» με ένα αρχείο ανά
είδος δεδομένων· μην τα αλλάζεις με το χέρι. Από την έκδοση 1.4 το κινητό ανοίγει αμέσως με ό,τι είδε την τελευταία
φορά, ακόμα κι όταν το πρόγραμμα «ξυπνάει» (μια μικρή σημείωση το λέει) και τα νέα έρχονται μόνα τους.
1. Ιδιωτικό αποθετήριο για τα δεδομένα:  https://github.com/new
   Repository name: sf-kentro-data · Private · τσέκαρε «Add a README file» · Create repository.
2. Κλειδί (token) μόνο γι' αυτό το αποθετήριο:  https://github.com/settings/personal-access-tokens/new
   Token name: sf-kentro · Expiration: 1 χρόνος · Repository access: Only select repositories → sf-kentro-data ·
   Permissions → Repository permissions → Contents: Read and write · Generate token → αντέγραψέ το (github_pat_…).
3. Λογαριασμός Render με το GitHub σου:  https://dashboard.render.com/register  («GitHub»).
4. Νέο Blueprint:  https://dashboard.render.com/blueprints → «New Blueprint Instance» → διάλεξε το αποθετήριο
   alexdimaras/Sf-Kentriko (αν ζητήσει, «Configure GitHub» και δώσε πρόσβαση) → Branch: claude/friendly-sagan-bfjrkj.
   Συμπλήρωσε:
     SFK_GITHUB_DATA     alexdimaras/sf-kentro-data
     SFK_GITHUB_TOKEN    το κλειδί του βήματος 2
     SFK_ADMIN_USER      π.χ. alex
     SFK_ADMIN_PASSWORD  τουλάχιστον 10 χαρακτήρες
   → «Apply». Η πρώτη φορά θέλει 5-10 λεπτά.
   (Χωρίς Blueprint: New → Web Service → Public Git Repository: https://github.com/alexdimaras/Sf-Kentriko ·
    Branch claude/friendly-sagan-bfjrkj · Language Docker · Dockerfile Path app/Dockerfile · Docker Build Context
    Directory app · Instance Type Free · και οι παραπάνω μεταβλητές, συν SFK_SECRET_KEY = 40 τυχαίοι χαρακτήρες.)
5. Άνοιξε τη διεύθυνση που δείχνει το Render (π.χ. https://sf-kentro.onrender.com) και συνδέσου.
   Ρυθμίσεις → Δεδομένα: «Φύλαξη στο GitHub» πρέπει να γράφει ότι όλα είναι φυλαγμένα.
6. Να μην «κοιμάται» (προαιρετικό, συνιστάται): https://cron-job.org (δωρεάν) → Create cronjob →
   URL https://ΤΟ-ΟΝΟΜΑ.onrender.com/ping · κάθε 10 λεπτά. Χωρίς αυτό κοιμάται μετά από 15′ χωρίς χρήση, το πρώτο
   άνοιγμα θέλει περίπου 1 λεπτό και οι ημερήσιες εργασίες γίνονται μόνο όσο είναι ξύπνιο. Το δωρεάν όριο του Render
   (750 ώρες τον μήνα) φτάνει για ΕΝΑ πρόγραμμα ανοιχτό όλο τον μήνα.
7. Κινητό: «Προσθήκη στην αρχική οθόνη». Οι άλλοι: Ρυθμίσεις → Χρήστες (λογαριασμός ο καθένας) και Ρυθμίσεις → Κινητό (QR).
8. Όταν γυρίσεις σπίτι: στο παλιό πρόγραμμα του υπολογιστή «Λήψη αντιγράφου» και εδώ «Επαναφορά από αρχείο»
   (Ρυθμίσεις → Δεδομένα). Οι κωδικοί B2B ξαναγράφονται μία φορά.
ΟΡΙΑ (τίμια): δωρεάν μηχάνημα 512 MB / 0,1 CPU — οι μεγάλες εργασίες (έρευνα αγοράς) είναι πιο αργές· σε σπάνιες
περιπτώσεις το Render ζητάει κάρτα για επαλήθευση (τότε: επιλογή Δ, GitHub Codespaces)· το κλειδί του GitHub λήγει σε
έναν χρόνο (το πρόγραμμα το λέει στις Ρυθμίσεις → Δεδομένα· φτιάχνεις νέο και το αλλάζεις στο Render → Environment).
Αν το GitHub δεν απαντήσει στην εκκίνηση, το πρόγραμμα ανοίγει αλλά ΔΕΝ γράφει τίποτα πάνω στα φυλαγμένα δεδομένα.

================================================================================
★★ ΚΟΙΝΗ ΒΑΣΗ ΔΕΔΟΜΕΝΩΝ (SUPABASE) ΚΑΙ ΥΠΟΛΟΓΙΣΤΕΣ ΤΩΝ ΜΑΓΑΖΙΩΝ — δωρεάν, χωρίς κάρτα (έκδοση 1.6)
================================================================================
ΤΙ ΚΕΡΔΙΖΕΙΣ
- Τα δεδομένα μένουν σε μια κανονική βάση PostgreSQL (Supabase, δωρεάν) αντί για αρχεία στο GitHub: κάθε αλλαγή
  φυλάγεται σε 30 δευτερόλεπτα, με αριθμό έκδοσης, ώστε δύο αλλαγές την ίδια στιγμή να μη σβήνει η μία την άλλη.
  Το GitHub μένει ως ΑΝΤΙΓΡΑΦΟ ΑΣΦΑΛΕΙΑΣ (μία φορά τη μέρα).
- Τα PC των μαγαζιών κάνουν τη βαριά δουλειά (σήμερα: την έρευνα τιμών, ένα κατάστημα τη φορά) και το μικρό
  μηχάνημα του Render μένει γρήγορο για εσένα. Αν κλείσει ένα PC, η δουλειά του πάει σε άλλο μέσα σε 90″·
  αν δεν υπάρχει κανένα ανοιχτό για 10 λεπτά, την κάνει το Render όπως πριν (πιο αργά).
- «Ρυθμίσεις → Ιστορικό ενεργειών»: ποιος ενέκρινε, άλλαξε ή αφαίρεσε τι και πότε.
Και τα δύο είναι προαιρετικά και ανεξάρτητα: χωρίς βάση και χωρίς PC όλα δουλεύουν όπως πριν.

ΑΣΦΑΛΕΙΑ (τι βλέπει ποιος)
- Τον κωδικό της βάσης τον ξέρει ΜΟΝΟ το Render (μεταβλητή SFK_DATABASE_URL). Τα PC δεν τον έχουν ποτέ.
- Κάθε PC έχει δικό του κλειδί, που το παίρνει μία φορά με κωδικό σύζευξης (8 χαρακτήρες, 15 λεπτά, μία χρήση).
  Το κλειδί φυλάγεται κλειδωμένο από τα Windows του PC· στο cloud μένει μόνο το «αποτύπωμά» του. «Αφαίρεση» στις
  Ρυθμίσεις → Υπολογιστές και το PC δεν μπαίνει πια.
- Τα PC διαβάζουν μόνο τους δημόσιους καταλόγους των ανταγωνιστών και τα ονόματα/κωδικούς/τιμές των δικών μας
  προϊόντων. Δεν βλέπουν χρήστες, κωδικούς B2B ή ρυθμίσεις. Δεν γράφουν ΠΟΤΕ στα sites. Ό,τι στείλουν το ελέγχει το
  cloud πριν το κρατήσει, και καμία αλλαγή στα προϊόντα δεν γίνεται χωρίς τη δική σου έγκριση.

1. ΛΟΓΑΡΙΑΣΜΟΣ SUPABASE (από το κινητό, 5 λεπτά)
   https://supabase.com/dashboard/sign-up → «Continue with GitHub».
   «New project» · Name: sf-kentro · Database Password: «Generate a password» και ΚΡΑΤΑ ΤΟΝ (μόνο γράμματα και
   αριθμοί είναι πιο απλό) · Region: «Central EU (Frankfurt)» (εκεί είναι και το Render) · Plan: Free ·
   «Create new project». Θέλει 1-2 λεπτά.
2. Η ΔΙΕΥΘΥΝΣΗ ΤΗΣ ΒΑΣΗΣ
   Στη σελίδα του project, πάνω: κουμπί «Connect» → καρτέλα «Connection String» → Type: URI →
   διάλεξε «Session pooler» (ΟΧΙ «Direct connection»: το Render δεν τη φτάνει) → αντέγραψε τη γραμμή, που μοιάζει με
     postgresql://postgres.abcdefgh:[YOUR-PASSWORD]@aws-0-eu-central-1.pooler.supabase.com:5432/postgres
   και βάλε στη θέση του [YOUR-PASSWORD] τον κωδικό του βήματος 1 (χωρίς τις αγκύλες).
   (Αν ο κωδικός έχει σύμβολα όπως @ # / ?, γράψε τα κωδικοποιημένα: @ → %40, # → %23, / → %2F, ? → %3F.)
3. ΣΤΟ RENDER
   https://dashboard.render.com → sf-kentro → Environment → «Add Environment Variable»:
     SFK_DATABASE_URL   η γραμμή του βήματος 2
   (Προαιρετικά, για έλεγχο ότι μιλάει πράγματι με τη Supabase: Supabase → Project Settings → Database →
    «SSL Configuration» → «Download certificate», άνοιξέ το με το Σημειωματάριο και βάλε όλο το κείμενο στη
    μεταβλητή SFK_DB_CA. Χωρίς αυτό η σύνδεση είναι πάλι κρυπτογραφημένη.)
   Άφησε τα SFK_GITHUB_DATA και SFK_GITHUB_TOKEN όπως είναι: τώρα κρατούν το ημερήσιο αντίγραφο.
   «Save Changes» → το Render ξεκινά ξανά (2-5 λεπτά).
4. ΕΛΕΓΧΟΣ
   Την πρώτη φορά, με άδεια βάση, το πρόγραμμα φέρνει μόνο του όλα τα δεδομένα από το GitHub. Ρυθμίσεις →
   Δεδομένα: «Φύλαξη» πρέπει να γράφει «βάση δεδομένων» και ότι όλα είναι φυλαγμένα. Ρυθμίσεις → Υπολογιστές:
   «όπου φυλάγονται τα δεδομένα: βάση δεδομένων».
5. ΥΠΟΛΟΓΙΣΤΕΣ ΤΩΝ ΜΑΓΑΖΙΩΝ (σε κάθε PC που θέλεις να βοηθάει· Windows 10/11, 64-bit, ακόμα και παλιό)
   - Στο PC: κατέβασε τον φάκελο του προγράμματος (περίπου 40 MB, περιέχει και το node.exe):
       https://github.com/alexdimaras/Sf-Kentriko/archive/refs/heads/claude/friendly-sagan-bfjrkj.zip
     Δεξί κλικ στο zip → Ιδιότητες → τσέκαρε «Κατάργηση αποκλεισμού» → OK → δεξί κλικ → «Εξαγωγή όλων…» →
     π.χ. C:\SF-Kentro. Μέσα στον φάκελο που βγήκε: διπλό κλικ στο «SF-Kentro-Worker.cmd».
     (Αν βγει «Τα Windows προστάτευσαν τον υπολογιστή σας»: «Περισσότερες πληροφορίες» → «Εκτέλεση οπωσδήποτε».)
   - Στο πρόγραμμα (από οπουδήποτε, ως διαχειριστής): Ρυθμίσεις → Υπολογιστές → «Νέος κωδικός».
   - Στο μαύρο παράθυρο του PC γράψε τη διεύθυνση (π.χ. https://sf-kentro.onrender.com) και τον κωδικό.
   Τέλος. Ξεκινά μόνο του με τα Windows, κρυφά, με χαμηλή προτεραιότητα (δεν σε καθυστερεί), και σε laptop
   χωρίς φορτιστή δεν παίρνει δουλειά. Για να σταματήσει: ξανά διπλό κλικ στο SF-Kentro-Worker.cmd → 3.
   Δεν θέλει κωδικό διαχειριστή των Windows. Ημερολόγιο: %APPDATA%\SF-Kentro-Worker\worker.log
ΑΝΤΙΓΡΑΦΑ ΚΑΙ ΕΠΑΝΑΦΟΡΑ
- Κάθε μέρα, με την πρώτη αποθήκευση, γίνεται στο GitHub ένα αντίγραφο με ημερομηνία (branch «backup-ΗΗΗΗ-ΜΜ-ΗΗ»),
  που δεν αλλάζει ποτέ μετά. Κρατιούνται τα 14 τελευταία ημερήσια και 8 εβδομαδιαία (Κυριακή).
- Επαναφορά σε μια μέρα (π.χ. μετά από λάθος): Render → sf-kentro → Environment → πρόσθεσε
    SFK_RESTORE_FROM   backup-2026-11-20   (η μέρα που θέλεις, όπως φαίνεται στα branches του αποθετηρίου δεδομένων)
  → Save Changes. Στην εκκίνηση τα δεδομένα εκείνης της μέρας γράφονται στη βάση (μία φορά). Μετά ΣΒΗΣΕ τη μεταβλητή.
- Η σύνδεση με τη βάση είναι πάντα κρυπτογραφημένη. Για να ελέγχεται και η ταυτότητα της βάσης βάλε το SFK_DB_CA
  (βήμα 3)· με SFK_DB_TLS=verify το πρόγραμμα αρνείται να συνδεθεί χωρίς αυτό.
ΟΡΙΑ (τίμια)
- Supabase δωρεάν: 500 MB (το πρόγραμμα σήμερα χρειάζεται περίπου 30-60 MB· Ρυθμίσεις → Δεδομένα δείχνει πόσο).
  Αν το project μείνει μία εβδομάδα χωρίς καμία χρήση, η Supabase το «παγώνει»: το ξαναξυπνάς με «Restore» στη
  σελίδα του. Με το πρόγραμμα ανοιχτό (και το cron-job.org του βήματος 6 πιο πάνω) αυτό δεν γίνεται.
- Η Supabase δωρεάν δεν κρατά δικά της αντίγραφα· γι' αυτό το πρόγραμμα κρατά ένα κάθε μέρα στο GitHub.
- Αν η βάση δεν απαντά στην εκκίνηση, το πρόγραμμα ανοίγει αλλά ΔΕΝ γράφει τίποτα πάνω της μέχρι να απαντήσει.
- Η κατανεμημένη δουλειά είναι σήμερα η έρευνα τιμών. Οι αναγνώσεις των sites (μόνο ανάγνωση) γίνονται ακόμα στο cloud.

================================================================================
Α. ORACLE CLOUD «ALWAYS FREE» — ΒΗΜΑ ΒΗΜΑ (μία φορά, περίπου 30 λεπτά)
================================================================================
1. ΛΟΓΑΡΙΑΣΜΟΣ
   - oracle.com/cloud/free → «Start for free».
   - Home Region: μια κοντινή, π.χ. «Germany Central (Frankfurt)» ή «Italy Northwest (Milan)». ΔΕΝ αλλάζει μετά.
   - Ζητάει κάρτα για επιβεβαίωση ταυτότητας. Οι πόροι «Always Free» δεν χρεώνονται.
2. ΜΗΧΑΝΗΜΑ: Compute → Instances → Create instance
   - Image: «Canonical Ubuntu» (24.04).
   - Shape: Ampere → VM.Standard.A1.Flex, 1 OCPU και 6 GB μνήμη (μέσα στο δωρεάν και περισσεύει).
     Αν γράψει «Out of capacity»: άλλο «Availability domain», ή ξανά σε λίγες ώρες, ή το VM.Standard.E2.1.Micro
     (επίσης δωρεάν· αρκεί — το πρόγραμμα βάζει μόνο του swap για τη μικρή μνήμη).
   - Add SSH keys: «Generate a key pair for me» → «Save private key». Κράτα το αρχείο .key: είναι το κλειδί.
   - Create. Όταν γίνει «Running», σημείωσε τη «Public IP address».
3. ΠΟΡΤΕΣ 80 ΚΑΙ 443 (για να ανοίγει η σελίδα)
   Στη σελίδα του instance πάτα το Subnet → Security Lists → «Default Security List» → «Add Ingress Rules»:
     Source CIDR 0.0.0.0/0 · IP Protocol TCP · Destination Port Range 80,443 → Add Ingress Rules.
4. ΔΙΕΥΘΥΝΣΗ (μία από τις δύο, και οι δύο δωρεάν)
   - Με το domain σας: εκεί που ρυθμίζετε τα DNS του site, πρόσθεσε εγγραφή τύπου A με όνομα «kentro» και τιμή
     τη Public IP. Η διεύθυνση γίνεται π.χ. kentro.specialforces.gr.
   - Χωρίς domain: duckdns.org (σύνδεση με Google ή GitHub) → γράψε ένα όνομα, π.χ. sf-kentro, και στο
     «current ip» τη Public IP. Η διεύθυνση γίνεται sf-kentro.duckdns.org.
5. ΑΝΕΒΑΣΜΑ ΚΑΙ ΕΓΚΑΤΑΣΤΑΣΗ — ένα διπλό κλικ
   Στον φάκελο SF-Kentro του υπολογιστή σου: διπλό κλικ στο «SF-Kentro-Cloud.cmd». Ζητάει:
     - την Public IP,
     - το αρχείο .key (σύρε το μέσα στο μαύρο παράθυρο και πάτα Enter),
     - τη διεύθυνση (π.χ. kentro.specialforces.gr).
   Την πρώτη φορά ρωτάει «Are you sure you want to continue connecting» → γράψε yes και Enter.
   Θέλει 5-10 λεπτά. Στο τέλος γράφει τη διεύθυνση και τον «κωδικό αρχικής ρύθμισης».
   (Το https μπαίνει μόνο του, με δωρεάν πιστοποιητικό Let's Encrypt.)
6. ΠΡΩΤΗ ΣΥΝΔΕΣΗ: άνοιξε τη διεύθυνση → γράψε τον κωδικό αρχικής ρύθμισης → φτιάξε τον λογαριασμό σου
   (διαχειριστής).
7. ΤΑ ΔΕΔΟΜΕΝΑ ΣΟΥ (μία φορά)
   - Στον υπολογιστή που δουλεύεις τώρα (SF-Kentro.cmd): Ρυθμίσεις → Δεδομένα → «Λήψη αντιγράφου».
   - Στον διακομιστή, από τον browser: Ρυθμίσεις → Δεδομένα → «Επαναφορά από αρχείο…» → διάλεξε το αρχείο.
   - Οι κωδικοί B2B των αντιπροσώπων είναι κλειδωμένοι στα Windows του παλιού υπολογιστή και ΔΕΝ ανοίγουν αλλού
     (έτσι πρέπει). Ξαναγράψ’ τους μία φορά στον διακομιστή (Αντιπρόσωποι → B2B).
8. ΧΡΗΣΤΕΣ: Ρυθμίσεις → Χρήστες → ένας λογαριασμός για κάθε άτομο. «Χρήστης» = όλη η δουλειά,
   «Διαχειριστής» = και ρυθμίσεις / ασφάλεια / χρήστες / αντίγραφα.
9. ΚΙΝΗΤΑ: Ρυθμίσεις → Κινητό → σκάναρε το QR (δες «ΣΤΟ ΚΙΝΗΤΟ» πιο κάτω).

ΜΟΝΟ ΑΠΟ ΚΙΝΗΤΟ (χωρίς υπολογιστή, χωρίς SSH): στο βήμα 2, στο «Advanced options → Management», τσέκαρε «Paste cloud-init
script» και επικόλλησε το περιεχόμενο του αρχείου deploy/cloud-init.sh (αλλάζεις μόνο τις τρεις πρώτες γραμμές: διεύθυνση,
όνομα και κωδικό διαχειριστή). Στο SSH keys διάλεξε «No SSH keys». Το μηχανήμα στήνεται μόνο του σε 10-15 λεπτά και
ανοίγεις https://η-διεύθυνσή-σου/. Η διεύθυνση: duckdns.org (σύνδεση με Google), όνομα της επιλογής σου και, μόλις δεις
τη Public IP του μηχανήματος, γράφεις την IP στο duckdns.

ΝΕΑ ΕΚΔΟΣΗ: βγάλε τον νέο φάκελο και ξανά διπλό κλικ στο SF-Kentro-Cloud.cmd (θυμάται IP, κλειδί και διεύθυνση·
πατάς μόνο Enter). Τα δεδομένα μένουν στον διακομιστή.

ΤΑ «ΨΙΛΑ ΓΡΑΜΜΑΤΑ» ΤΟΥ ΔΩΡΕΑΝ — τίμια
- Η Oracle μπορεί να σταματήσει («reclaim») δωρεάν μηχανήματα που μένουν σχεδόν αδρανή για μέρες. Όσοι το
  χρησιμοποιούν αναφέρουν ότι με «Upgrade to Pay As You Go» (στον λογαριασμό) αυτό δεν γίνεται και τα «Always
  Free» μένουν δωρεάν. Αν το κάνεις, βάλε και ειδοποίηση κόστους στο 1 € (Billing → Budgets) για σιγουριά.
- Κατέβαζε μια «Λήψη αντιγράφου» κάθε εβδομάδα (Ρυθμίσεις → Δεδομένα) και κράτα τη εκτός cloud (USB, OneDrive).
  Ο διακομιστής κρατάει μόνος του και ένα αντίγραφο κάθε μέρα (14 μέρες).
- Το δωρεάν πακέτο αλλάζει πού και πού (αναφέρθηκε μείωση των δωρεάν Ampere το 2026). Το 1 OCPU / 6 GB που
  προτείνεται εδώ χωράει και στο μικρότερο.
- Μετά από κάθε επανεκκίνηση του διακομιστή (και μετά από κάθε νέα έκδοση), αν έχεις PIN για τα B2B, ένας
  διαχειριστής το βάζει μία φορά (Ρυθμίσεις → Ασφάλεια) για να διαβάζονται τα B2B στην ημερήσια ενημέρωση.

1. github.com → Settings → Codespaces → Secrets → New secret, δύο φορές (Repository access: Sf-Kentriko):
     KENTRO_ADMIN_USER      π.χ. alex
     KENTRO_ADMIN_PASSWORD  τουλάχιστον 10 χαρακτήρες
   Στην ίδια σελίδα, «Default idle timeout»: βάλε 240 λεπτά (αλλιώς κοιμάται μετά από 30′).
2. github.com/alexdimaras/Sf-Kentriko → διάλεξε το branch  claude/friendly-sagan-bfjrkj  → Code → Codespaces →
   «Create codespace on claude/friendly-sagan-bfjrkj». Η πρώτη φορά θέλει 3-5 λεπτά.
3. Όταν είναι έτοιμο, στο παράθυρο του Codespace: καρτέλα «Ports» → θύρα 17321 → εικονίδιο υδρογείου (Open in Browser).
   Αντίγραψε τη διεύθυνση (https://…-17321.app.github.dev) και βάλ' τη στους σελιδοδείκτες / στην αρχική οθόνη.
4. Συνδέεσαι με το KENTRO_ADMIN_USER και τον κωδικό. Μετά: «Ανάγνωση από τα sites».
Κάθε επόμενη μέρα: github.com/codespaces → το Codespace → «Start» (ή απλώς άνοιξε τη διεύθυνση του βήματος 3).
ΟΡΙΑ: κοιμάται όταν δεν δουλεύεις (οι ημερήσιες αυτόματες εργασίες τρέχουν μόνο όσο είναι ξύπνιο)· σβήνεται μετά από
30 μέρες χωρίς χρήση — κατέβαζε «Λήψη αντιγράφου» (Ρυθμίσεις → Δεδομένα)· αν περάσεις το δωρεάν όριο, σταματά
(δεν χρεώνεσαι αν το όριο ξόδων μένει στο 0). Η σελίδα ανοίγει μόνο όταν είσαι συνδεδεμένος στο GitHub και μετά με τον
δικό σου κωδικό στο πρόγραμμα. Το αποθετήριο είναι δημόσιο, αλλά δεν περιέχει δεδομένα ή κωδικούς.
Τα τωρινά δεδομένα του υπολογιστή δεν υπάρχουν εκεί: ξεκινάς καθαρός. Όταν γυρίσεις σπίτι, «Λήψη αντιγράφου» από τον
υπολογιστή και «Επαναφορά από αρχείο» εδώ (ή ανάποδα).

Β. ΕΝΑ PC ΤΟΥ ΜΑΓΑΖΙΟΥ ΩΣ ΔΙΑΚΟΜΙΣΤΗΣ (δωρεάν, χωρίς κάρτα, χωρίς λογαριασμούς)
================================================================================
1. Κλείσε το SF-Kentro (αν είναι ανοιχτό) και άνοιξε το «SF-Kentro-Server.cmd» από τον ίδιο φάκελο.
   Τα δεδομένα είναι τα ίδια: δεν μεταφέρεις τίποτα. Ανοίγει μόνο του και ο browser.
2. Τα Windows ρωτάνε για το τείχος προστασίας: τσέκαρε «Ιδιωτικά δίκτυα» → «Να επιτρέπεται η πρόσβαση».
   (Αν το δίκτυο του μαγαζιού είναι δηλωμένο «Δημόσιο», άλλαξέ το σε «Ιδιωτικό»: Ρυθμίσεις → Δίκτυο.)
3. Πρώτη φορά: φτιάξε τον λογαριασμό σου με τον κωδικό που γράφει το μαύρο παράθυρο.
4. Ρυθμίσεις → Χρήστες: ένας λογαριασμός για κάθε άτομο.
5. Ρυθμίσεις → Κινητό: σκάναρε το QR με κάθε κινητό. Τα άλλα PC του μαγαζιού ανοίγουν τη διεύθυνση που γράφει
   εκεί (π.χ. http://192.168.1.20:17321).
6. Για να ξεκινάει μόνο του το πρωί: Win+R → γράψε shell:startup → Enter → βάλε εκεί μια συντόμευση του
   SF-Kentro-Server.cmd.
ΟΡΙΑ: μόνο μέσα στο δίκτυο αυτού του μαγαζιού (όχι από Wi-Fi επισκεπτών, όχι από τα δεδομένα του κινητού) και
μόνο όσο είναι ανοιχτό αυτό το PC. Η ημερήσια έρευνα γίνεται όταν ανοίξει το πρωί.
Για το ΑΛΛΟ μαγαζί και για το κινητό έξω από το μαγαζί: το Α.
ΠΟΤΕ μην ανοίξεις θύρα (port forwarding) στο ρούτερ για το πρόγραμμα.
(Υπάρχουν και εφαρμογές ιδιωτικού δικτύου, όπως το Tailscale, αλλά το δωρεάν πακέτο τους είναι για προσωπική
χρήση· για επιχείρηση θέλουν συνδρομή. Γι' αυτό η δωρεάν πρόταση για «από παντού» είναι το Α.)

ΣΤΟ ΚΙΝΗΤΟ (μία φορά, ένα λεπτό)
================================================================================
1. Σκάναρε το QR (Ρυθμίσεις → Κινητό, σε έναν υπολογιστή) με την κάμερα, ή γράψε τη διεύθυνση στον browser.
2. Όνομα και κωδικός, και τσέκαρε «Μείνε συνδεδεμένος σε αυτή τη συσκευή»: μένεις μέσα έως 30 μέρες χωρίς χρήση.
   Μόνο στο δικό σου κινητό, όχι σε ξένη συσκευή.
3. Βάλ' το στην αρχική οθόνη, για να ανοίγει σαν εφαρμογή:
   - iPhone (Safari): κουμπί Κοινοποίηση (τετράγωνο με βέλος) → «Προσθήκη στην οθόνη Αφετηρίας».
   - Android (Chrome): μενού ⋮ → «Εγκατάσταση εφαρμογής» ή «Προσθήκη στην αρχική οθόνη».
Στο κινητό: κάτω μπάρα με Σήμερα / Διορθώσεις / Τιμές / Προϊόντα / Μενού. Ό,τι εγκρίνεις εκεί φαίνεται αμέσως
στα PC. Τα αρχεία για WooCommerce τα φτιάχνεις καλύτερα από PC (εκεί τα ανεβάζεις στο site).
Χάθηκε ένα κινητό; Ρυθμίσεις → Χρήστες → «Ανοιχτές συνδέσεις» → «Αποσύνδεση» δίπλα του, και άλλαξε τον κωδικό.

ΑΣΦΑΛΕΙΑ ΣΤΗ ΛΕΙΤΟΥΡΓΙΑ ΔΙΑΚΟΜΙΣΤΗ
================================================================================
- Κάθε άτομο με δικό του όνομα και κωδικό (τουλάχιστον 10 χαρακτήρες). Οι κωδικοί δεν αποθηκεύονται·
  μόνο ένα «αποτύπωμα» scrypt που δεν γυρίζει πίσω.
- 5 λάθος κωδικοί → αναμονή 1 λεπτού που διπλασιάζεται (ανά χρήστη και ανά διεύθυνση).
- Η σύνδεση λήγει μετά από αδράνεια (Ρυθμίσεις → Ασφάλεια, προεπιλογή 30′). Με «Μείνε συνδεδεμένος» στο
  κινητό: 30 μέρες. Ο διαχειριστής βλέπει κάθε συνδεδεμένη συσκευή και αποσυνδέει όποια θέλει.
- Cookie σύνδεσης HttpOnly + SameSite=Strict (+ Secure με https) και ξεχωριστό κλειδί ανά σύνδεση σε κάθε
  αίτημα: άλλες σελίδες του browser δεν μπορούν να κάνουν τίποτα στο πρόγραμμα.
- Στο cloud: μόνο https (κρυπτογραφημένα), δεκτή μόνο η δική σας διεύθυνση.
- Ρυθμίσεις, ασφάλεια, χρήστες, αντίγραφα και επαναφορά: μόνο διαχειριστές.
- Κωδικοί B2B: κρυπτογραφημένοι στον διακομιστή, και επιπλέον με PIN (Ρυθμίσεις → Ασφάλεια).
- Κωδικοί διαχειριστή (admin) των sites: δεν χρειάζονται και δεν αποθηκεύονται πουθενά. Το πρόγραμμα ΔΕΝ γράφει
  τίποτα στα sites· φτιάχνει αρχεία που ανεβάζεις εσύ.

ΓΙΑ ΠΡΟΧΩΡΗΜΕΝΟΥΣ
================================================================================
Χωρίς το SF-Kentro-Cloud.cmd (οποιοσδήποτε διακομιστής Ubuntu — και πληρωμένος VPS, αν κάποτε χρειαστεί):
  ανέβασε τους φακέλους app και deploy και τρέξε:   sudo bash deploy/install-server.sh kentro.example.gr
Στον διακομιστή (μέσα στο sf-kentro/deploy):
  Κατάσταση / logs:        sudo docker compose logs kentro        (https: sudo docker compose logs caddy)
  Επανεκκίνηση:            sudo docker compose restart
  Όλος ο φάκελος δεδομένων: sudo docker compose cp kentro:/data ./antigrafo-$(date +%F)
Ρυθμίσεις διακομιστή (μεταβλητές περιβάλλοντος):
  SFK_MODE=server            λειτουργία διακομιστή
  SFK_PORT=17321             θύρα
  SFK_HOST=0.0.0.0           σε ποιες διευθύνσεις ακούει
  SFK_DATA=/data             φάκελος δεδομένων
  SFK_ALLOWED_HOSTS=kentro.specialforces.gr   ποιες διευθύνσεις δέχεται (κενό = όλες, για το τοπικό δίκτυο)
  SFK_TRUST_PROXY=1          πίσω από Caddy / nginx (σωστή IP και https)
  SFK_SECURE_COOKIE=1        cookie μόνο με https
  SFK_ADMIN_USER / SFK_ADMIN_PASSWORD   ο πρώτος διαχειριστής χωρίς κωδικό αρχικής ρύθμισης
  SFK_DATABASE_URL=postgresql://…       κοινή βάση PostgreSQL (Supabase ή οποιαδήποτε· με SSL εκτός localhost)
  SFK_DB_CA=-----BEGIN CERTIFICATE…     το πιστοποιητικό της βάσης, για έλεγχο του διακομιστή της
  SFK_DB_SECONDS=30                     κάθε πόσα δευτερόλεπτα φυλάγονται οι αλλαγές στη βάση
  SFK_LEASE_MS / SFK_CLOUD_AFTER_MS     σε πόσο μια σιωπηλή εργασία πάει αλλού (90000) / σε πόσο την κάνει το cloud (600000)
Υπολογιστής που βοηθάει, χωρίς Windows (Linux/macOS με Node 22, στον φάκελο app):
  node worker.js pair https://ΤΟ-ΟΝΟΜΑ.onrender.com ABCD-2345      μία φορά
  node worker.js                                                    δουλεύει (π.χ. ως υπηρεσία systemd)
